## ⚙️ Technical Architecture & PTX Math

BitCrack CUDA Engine achieves extreme point generation rates by circumventing conventional high-level C++ abstraction overheads:

```
  ┌────────────────────────────────────────────────────────────────────────┐
  │                         NVIDIA GPU STREAMING MULTIPROCESSOR            │
  │                                                                        │
  │   ┌────────────────────┐    ┌───────────────────┐    ┌─────────────┐   │
  │   │ 32-Thread Warp     │ ─> │ Montgomery Batch  │ ─> │ LDS Stride  │   │
  │   │ Cooperative Group  │    │ Inversion (invMod)│    │ Point Cache │   │
  │   └────────────────────┘    └───────────────────┘    └──────┬──────┘   │
  │                                                             │          │
  │                                                             ▼          │
  │   ┌────────────────────┐    ┌───────────────────┐    ┌─────────────┐   │
  │   │ Key Match / Trap   │ <─ │ RIPEMD-160 LUT    │ <─ │ SHA-256     │   │
  │   │ Collision Buffer   │    │ (lop3.b32 Opcode) │    │ Funnelshift │   │
  │   └────────────────────┘    └───────────────────┘    └─────────────┘   │
  └────────────────────────────────────────────────────────────────────────┘
```

1. **PTX Assembly secp256k1 Math**: Hand-crafted 256-bit modular addition (`addModP`) and subtraction (`subModP`) in inline PTX assembly with zero register spilling and branchless carry propagation.
2. **Cooperative Warp Batch Inversion**: 32 threads in each warp invert 32 field elements simultaneously via Montgomery's simultaneous inversion trick, replacing 32 heavy extended Euclidean inversions with a single modular inversion.
3. **LDS Zero-Latency Stride Caching**: Precomputed secp256k1 generator stride points (`_INC_X`, `_INC_Y`) are loaded into GPU Shared Memory (`__shared__`) per block, eliminating high-latency global memory fetches.
4. **Hardware-Accelerated Bitwise LUTs**: SHA-256 and RIPEMD-160 hashing inner loops utilize hardware-level `lop3.b32` 3-input logic opcodes and `__funnelshift_r` barrel shifters.

## 🎮 Dual Engine CLI Reference

### 1. `cuBitCrack.exe` — Linear Multi-Hash Engine ($O(N)$)
Designed for unspent Bitcoin addresses, bulk lists of millions of target addresses, and sequential key discovery.

```cmd
cuBitCrack.exe -d 0 -b 1024 -t 256 -p 32 -c --keyspace 4000000000:7FFFFFFFFF -o found_keys.txt 1EeAxcprB2PpCnr34VfZdFrkUWuxyiNEFv
```

| Flag | Description | Default |
|:---|:---|:---:|
| `-d <id>` | Target NVIDIA GPU Device ID | `0` |
| `-b <blocks>` | Number of CUDA thread blocks | `1024` |
| `-t <threads>`| Number of threads per block | `256` |
| `-p <points>` | Points per thread per kernel call | `32` |
| `-c` | Search compressed public key format | Enabled |
| `--keyspace` | Hexadecimal start and end bounds | `1:FFFF...` |
| `-o <file>` | Output file for discovered private keys | `found.txt` |

<br/>

### 2. `RCKangaroo.exe` — Pollard's Kangaroo Engine ($O(\sqrt{N})$)
Optimized for solving targets with known public keys inside bounded bit ranges (e.g. Bitcoin Puzzles #1 through #160).

```cmd
RCKangaroo.exe -gpu 0 -dp 16 -range 66 -start 2000000000000000 -pubkey 03a20917...
```

| Flag | Description | Default |
|:---|:---|:---:|
| `-gpu <id>` | Target GPU index | `0` |
| `-dp <bits>` | Distinguished Point bit filter level | `16` |
| `-range <n>` | Keyspace range bit size (e.g. 66 for puzzle 66) | Auto |
| `-start <hex>`| Starting hexadecimal range offset | Required |
| `-pubkey <hex>`| Full secp256k1 compressed target public key | Required |
